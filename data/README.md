# Numerical datasets

The CSV files contain the selected agreement, resource, outcome, and attribution values. Full traces, individual injection logs, sampled-site lists, and per-draw predictions are generated by the execution tools and are not included in this download. Each CSV uses UTF-8, a header row, and decimal numbers. An empty field means unavailable, never zero.

## Agreement

The reference uses 10,000 draws with replacement per applicable application, architecture, and component, with seed 2026. Repeated coordinates remain separate draws. There are 14 RF, 7 SMEM, 14 L1D, and 14 L2 conditions on each architecture. Each condition receives equal weight; `Mean` weights the two architectures equally.

| File | Rows and columns |
|---|---|
| `agreement/overall.csv` | One row per architecture and its mean. SARA point inconsistency and known coverage are percentages. SARA whole proportion gap is the mean absolute difference of the three known outcome proportions, in percentage points. GEREM has separate SDC-rate gap and expected point inconsistency columns. |
| `agreement/class_proportions.csv` | Architecture and method, followed by Masked, SDC, and DUE absolute proportion gaps in percentage points. GEREM's `masked_gap_pp` compares non-SDC probability with FI Masked plus DUE. Its independent DUE field is empty. |
| `agreement/by_component.csv` | Component-level inconsistency and full-denominator outcome percentages. FI and SARA point use all requested draws. SARA whole uses complete bit-cycle population mass. GEREM's `non_sdc_pct` is probability mass, not an independently predicted Masked class. |
| `agreement/by_application.csv` | Application, architecture, method, and its condition-macro `inconsistency_value`. The unit is percent for point inconsistency and percentage points for SARA whole's distribution gap. |

SARA point inconsistency uses the same paired draws for which both FI and SARA are known. Whole proportions remove Unknown separately from the complete SARA population and the FI sample before comparing Masked, silent data corruption (SDC), and detected unrecoverable error (DUE). Known coverage retains the complete original denominator.

For GEREM, let `p` be the native SDC probability at a paired site. Its SDC-rate gap is the absolute difference between mean `p` and the observed FI SDC proportion, calculated within each condition before averaging. Its expected inconsistency averages `1-p` when FI is SDC and `p` when FI is Masked or DUE. No probability threshold or independent DUE classifier is used.

The FI oracle checks every declared output byte. Successful identical output is Masked; changed output is SDC; an admitted invalid execution or simulation-cycle watchdog is DUE. An interrupted infrastructure task is not a completed draw. Requested, applied, and consumed are different notions: a sampled draw can be successfully applied without a subsequent consumer. Those receipts belong to newly generated per-draw records, not the aggregate CSV schema.

## Resource costs

| File | Rows and columns |
|---|---|
| `performance/summary.csv` | Architecture and method. `speedup_over_fi_10000` is FI cumulative 10K active time divided by method active workflow time. `trace_gib` sums retained compressed input traces across 14 groups. `events_million` sums distinct capture records, counting a shared cache capture once. The two peak fields are the maximum complete-container high-water marks across the corresponding groups. The three time fields sum Collect, Prep, and Analyze seconds across the groups. `Mean` is the arithmetic architecture mean for each field, including ratios and peaks. |
| `performance/by_application.csv` | Application, architecture, method, and the same complete-workflow speedup definition. GEREM-200K uses twenty times the draws of FI-10K. |

Collect produces each method's necessary observations. Prep includes populations, sampling where needed, initial memory, and input binding. Analyze includes required reads, decoding, common preparation, prediction, aggregation, persistence, and cleanup. Compilation, independent checks, and additional diagnostic exports have separate boundaries. Historical FI-10K is the sum of completed append segments and retained active receipts. It is a cumulative workflow, not a newly timed independent 10K campaign. The SARA and GEREM workflows were measured on their own inputs.

SARA event counts are dynamic PTX records. GEREM counts storage-access and cache-ledger records. These are distinct input-volume measures. A GiB is 1,073,741,824 bytes. Peak memory includes all method processes, indices, and caches; it is not an estimate obtained by subtraction. I/O transfer volume is not used as a storage-size measurement. A pure profiling overhead ratio requires a separately matched unprofiled execution and is not supplied in these CSV files.

## Language-model and attribution data

| File | Definition |
|---|---|
| `language_model/outcomes.csv` | Complete five-layer Stories260K, one fixed token, batch one, all 512 logits, parallel SARA. Outcome fields are percentages of each component's complete population. Tiny positive SMEM SDC shares can round to zero at four decimal places. |
| `language_model/costs.csv` | Retained compressed trace GiB, complete method/container peak GiB, and complete active workflow seconds. SM75 combines input-equivalent completed Collect and Prep measurements with the accepted Analyze window, counting each once. SM86 uses its completed stages. The decimal precision shown in this CSV is the retained reported precision. |
| `evidence/sdc_attribution.csv` | Pooled SM75 and SM86 predicted SDC mass, assigned to mutually exclusive model-evidence categories. Values sum to 100 percent. `mdp`: memory-data propagation; `sct`: scalar computation; `cft`: copy forwarding; `pms`: predicate-mediated selection; `vas`: valid-address substitution; `ctrl`: changed-control sensitivity; `mixed_rf`: multiple RF evidence kinds. These are model evidence, rather than observed faulted executions. |

`python3 scripts/check_data.py` checks schema, numerical closure, equal-architecture means, and applicable-condition aggregation from the supplied CSVs. It does not regenerate omitted per-draw records. `scripts/metrics.py` contains the outcome and probability arithmetic for freshly generated paired results.
